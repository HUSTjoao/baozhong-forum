# 名称申请与管理员资料整理

用户入口 /universities/add、/majors/add，只接收 name（非空、最多 80 字）。页面仅一个名称输入，不要求用户提供介绍、地区、城市、学科、官网或图片。登录后提交，创建真实数据库里的 pending/isApproved=false 记录，提交者取当前登录账号；客户端额外字段不影响权限或资料。名称规范化去重，重复不创建第二条记录。被禁言账号不能提交。

用户可在“我的补充记录”查看整理中、已收录、暂未收录。公开后链接到正式学校或专业页面。旧浏览器 localStorage 记录不自动迁入。

管理员入口 /admin/catalog，通过服务器数据库当前 role 校验。管理员展开“整理资料”可核实并填写正式名称、介绍；学校还有地区、城市、层次、官网、资料来源、英文名及校训，专业选择所属学科。支持保存整理进度（仍 pending）、保存并公开、确认暂不收录。公开前要求至少 30 字介绍，学校要求地区和城市；链接只接受 https。重复正式名称拒绝。学校简介及 UniversityProfile 在同一事务中更新，避免公开页面缺资料。已完成处理的申请返回 409。

待整理学校/专业不出现在公开目录，学校详情不可直接访问。待整理内容不能被普通用户通过审核；申请列表默认仅显示本人的记录，scope=admin 需实时管理员权限。保存和公开接口 /api/catalog/[kind]/[id]/review，状态允许 pending/approved/rejected。

数据结构沿用原 University、UniversityProfile、Major，不需要数据库迁移。历史的完整 pending 申请仍可编辑后收录。暂未收录的同名申请暂不支持用户重提、管理员复审或填写拒绝理由。

## 验证

scripts/check-catalog-request.ts 仅允许本地 SQLite，创建临时数据后清理。覆盖名称提交、登录和管理权限、客户端伪造介绍/作者/审核状态不生效、规范化重复名称、管理员草稿、缺介绍/缺地区禁止公开、非法官网地址、公开目录、学校资料事务同步、重复处理冲突。浏览器验证只提交 name、显示成功及整理进度、管理员编辑展开，以及 1440/390 宽度无横向溢出。

## 服务器测试状态

阿里云 ECS 运行独立 baozhong-forum-test，监听 127.0.0.1:3001，通过私密端口转发在用户电脑 localhost:3002 访问。forum_db_v2 已完成 PostgreSQL 初始迁移、149 所大学及 192 个专业初始化、真实连接检查和注册发帖跨浏览器共享测试。旧 forum_db 和备份保留。不同电脑访问尚未验收，用户选择等待域名部署。

生产迁移在 prisma/migrations-postgresql，与本地 SQLite 分开。初始迁移不能直接套到旧库。db:seed:production 幂等导入目录，不创建演示账号或讨论。开发输出 .next-dev 与生产 .next 隔离；2GB ECS 构建使用 ECS_BUILD=1 NODE_OPTIONS="--max-old-space-size=1024" npm run build。为避免正在运行的生产进程引用旧资源，测试环境更新时停止测试进程再构建，成功后重启。正式公开上线还需依赖安全更新、系统维护、备份恢复验收、域名备案和 HTTPS。
