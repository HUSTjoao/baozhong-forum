# 管理员工作台

`/admin` 读取服务器业务数据库，不再读取浏览器 localStorage。`/api/admin` 为分页管理列表（每页 30 条）、搜索和统计，返回用户字段采用白名单，不返回密码、密码哈希或密钥。未登录 401，数据库中不是管理员 403。

功能：用户禁言与解除禁言；帖子删除（包括全部回复及点赞）；回复删除（包括后代跟帖及点赞，并更新回复计数）；寄语删除（点赞关联一并删除）；举报待处理/已处理/已忽略筛选。删除和禁言必须二次确认。大学/专业资料审核继续在 `/admin/catalog`，工作台上方和侧栏都有入口。

所有管理接口逐次读取数据库角色，旧 JWT 中的 admin 不构成授权。现有帖子/回复/寄语删除接口也已改用数据库当前角色。禁言由发表接口直接读取数据库状态，无需用户重新登录。管理员不能被禁言，用户状态接口不接受角色变更。

举报列表原接口也需当前管理员权限。举报提交验证目标确实存在且属于对应讨论，内容快照由数据库读取，不信任浏览器提交的文本。举报状态仅接受 resolved/ignored，处理过的举报返回 409；标记已处理不会自动删除内容，需先人工审核和删除违规内容。

## 初次设置管理员

先在当前部署网址注册个人账号，再在对应项目目录执行：

```bash
npx tsx scripts/set-admin.ts 注册账号
npx tsx scripts/set-admin.ts 注册账号 --apply
```

第一条仅预览，第二条赋予现有账号管理员权限（不创建账号，不读取或输出密码）。完成后退出重登，访问 `/admin`。只在受信任的服务器终端执行，不提供公开注册管理员或浏览器升权接口。切勿把密码填到命令中。

## 验证

`scripts/check-admin-integration.ts` 只允许本地 SQLite，针对本地 3000 开发服务器生成临时测试用户、帖子、回复、点赞与举报，finally 清理。覆盖未登录/普通用户/伪造旧管理员角色禁止访问、敏感字段隔离、禁言即时生效、非法状态拒绝、举报服务器快照、处理冲突、回复树/寄语点赞删除、撤权立即失效。

上线后仍需用服务器数据库里的真实管理员和普通账号进行同样的验收。当前范围不包括永久删除用户、浏览器调整角色、操作审计历史或恢复已删除内容；这些需要单独设计和数据迁移。

## 寄语点赞修复

旧点赞接口只返回 `{liked}`，客户端却读取 `data.message.likes`，在 React 状态更新函数中访问 undefined，造成页面渲染错误。接口现于事务中更新点赞关联和数量，并返回带安全用户字段与 likesRel 的 message；未公开寄语不可点赞，禁言状态从数据库读取。客户端校验返回对象，异常仅显示错误提示。回归覆盖点赞/取消、计数落库、寄语点赞关联删除，以及浏览器正常切换状态与不完整返回时页面仍可用。未对夸克本身的进程崩溃作无证据的保证，上线后需复测。

## 统一登录

登录页和公共导航不再显示管理员入口。管理员通过同一个账号密码登录页认证成功后直接进入 /admin；角色仍由数据库决定，不靠账号名称硬编码。

指定账号需要创建或重置密码时，受信任服务器终端使用 configure-admin.ts，密码从标准输入读取，bcrypt 加密保存。示例（密码隐藏输入，不作为命令参数或写入仓库）：

```bash
read -rsp '管理员密码: ' ADMIN_INPUT
printf '\n'
printf '%s' "$ADMIN_INPUT" | npx tsx scripts/configure-admin.ts 注册账号 --apply
unset ADMIN_INPUT
```

此操作会更新指定账号密码并授予管理员权限；不影响其他用户或内容。
